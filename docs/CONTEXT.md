# Worlds Beyond: Context

The up-to-date project reference for Worlds Beyond, a customizable homebrew D&D character sheet and combat system. **Implemented** features, **decided but unbuilt** mechanics and **undecided** ideas must be kept separate. Update these sections in place; git history already records individual PRs.

## Where things live

- **Rules:** Notion → [D&D > Game Systems](https://app.notion.com/p/351c72092efb8089812cd231debc3e74), including Stats, Action Points, Defenses, Magic, Status Effects, Equipment and [Death and Dying](https://app.notion.com/p/707a548ff2354d0ba02e7979ca9bda1c). Weavecasting is a separate system; don't mix it in.
- **Live site:** [Worlds Beyond on GitHub Pages](https://immortalwarlock427-debug.github.io/Worlds-Beyond/). Plain HTML/CSS/JS without a build step. README covers navigation; ARCHITECTURE describes modules/saves; ROADMAP tracks future work; AGENTS gives collaboration rules.
- **Local saves:** separate character (`worlds-beyond-sheet-v1`) and DM game (`worlds-beyond-game-v1`) records. v1 character JSON exports exclude map, fog and encounter data. The game holds map, fog, legacy tokens/foes and optional offline encounter.
- **Cloud character copies:** Supabase Auth and `wb_characters` owner-only RLS. The site auto-connects using the **public publishable** configuration; manual Save and Restore are separate from local character data. No cloud game/encounter sync.
- **Claude artifact:** build from merged `main` with `python3 tools/build_single.py`.

## How we play and work

- **Delivery priority:** finish the character sheet, custom abilities and phone workflows before expanding battlemaps, the DM Room, player-versus-player combat or live sessions. Preserve shared DOM-free rules and separate saves so those later views can reuse the completed character features.
- **In person:** each player has **their own phone** and character sheet. The DM uses a **computer and a phone**. All live-session designs must support separate devices, not assume shared browser storage.
- **Custom equipment:** items store their actual stats, dice multipliers and effects. Material names never determine their numbers; the sheet has no material taxonomy. Table presets are optional editable starting points.
- **Trust-based sheet:** players can customize and correct stats, resources and abilities. **Do not add anti-cheat or restrictive gameplay validation unless explicitly asked.** Account privacy, server access control and preventing accidental shared-data overwrites are separate security requirements.
- The DM levels characters at story milestones and discourages metagaming. Keep the interface editable/resettable for mistakes.
- Critically evaluate ideas; identify contradictions or unnecessary limits. Write 1.5× or 150% for multipliers.
- When a rule changes, reconcile Notion, the site and this context. **Do not append a new section for each PR.**

## What the site does (Draft 53)

The following features **already exist** in the live site:

- **Character interface:** Overview opens with Health, AP/reactions and current-form favorite abilities; profile details follow the live controls. Files and secondary views live in Character menu, with Clear sheet separated under Reset character. Favorite Use buttons share the Ability Library activation path. Overview, Attributes, Equipment, Abilities, Status Effects, Notes and Dice sub-tabs, plus separate Battlemap; portraits, vitals, Death Threshold/Trauma, Mana/Holy Power, AP, reactions, Wonder, concentration, manual overrides, rests, advancement, export/import and clearing the sheet.
- **Shared combat core:** `WBCombat` handles effective stats, gear, Armor Rating, AP, Surge, attacks, dual hits/criticals, resistance, defenses and death calculations. Character progression and shared combat formulas are reusable; dice UI is separate.
- **Character notes:** Notes holds session notes, backstory, personality, languages, and allies/connections as optional plain text. Session notes appear first; all fields support multiline text and travel through local saves, v1 exports/imports and manual cloud copies. Legacy characters start empty. Notes belong to the character across forms and rests; editing them never runs gameplay commands or rewrites an unchanged DM game.
- **Dice and recent rolls:** Dice offers validated free expressions such as `3d6+2`, rolling exactly the expression without costs or effects. The newest 20 timestamped results belong to the character and travel through local/v1/manual-cloud saves. Checks, weapon/ability attacks and damage, defenses, consumable healing, stat generation and short-rest/status rolls record actual results. Wonder adds a new roll; Defy Fate and opportunity conversion revise the existing result without rerolling. Read-only expandable details contain no action controls; opening history never spends or applies anything. Clear recent rolls affects only the history.
- **Consumables:** Equipment has a separate character-wide consumables list with names, descriptions, editable whole quantities and optional healing dice. Use spends one item only after validating its quantity and complete roll. Healing opens the normal popup; Apply healing to me uses the existing Health/Trauma/max rules once, while other costs/effects resolve at the table. Editing definitions retains the current quantity. Forms, turns, combat changes and rests never replenish these items. Legacy characters start empty, and local/v1/manual-cloud saves preserve the list.
- **Equipment:** Pack, Forge, worn slots, weapon actions and bonuses. Named forms use one shared inventory but may wear different equipment profiles.
- **Custom Ability Library:** create/edit/duplicate/delete/favorite, categories, search/sort/filters, compact display, optional AP/Mana/Holy Power/custom-resource costs, Use action, optional attack/damage rolls and save DCs, limited uses, held creations, cooldown, duration, ongoing numerical effects and turn/long-rest processing. Active effects support movement, Armor Rating, Evasion, stat scores and custom-resource maximums.
- **Forms and portraits:** named ability loadouts can be bidirectionally linked to portraits. Forms change available abilities, can adjust effective stats, gate custom resources/Mana visibility and swap worn equipment. Cooldowns, charges, effects and resource balances carry over. **Named forms may charge optional AP and/or resource entry costs; returning to Base and reselecting the current form are free.** Effective scores may exceed 28 and unlock milestones.
- **Shared character payments:** `WBCharacter` derives AP and Mana/Holy Power from saved data and applies pure payment/correction commands. Command AP is spent first; AP/Mana costs are validated together. Blank trackers still mean full, hidden Mana retains its balance, and form entry pays against the source gear profile. Ability Use, named form selection and portrait selection now apply as complete transactions: AP/Mana/custom costs, uses, capacity, cooldown/duration and gear/portrait changes commit together. Failed operations leave the original character untouched. Turn/rest processing now uses atomic commands; broader transaction Undo remains a follow-up.
- **Shared Health commands:** Health current/maximum values, damage, healing, stability, Trauma corrections and treatment use DOM-free `WBCharacter` derivation/commands. Ordinary and potion healing share the same recovery/max logic; damage receives the final post-defense amount once. Blank current Health still means full, manual values stay editable above/below maximum, Death's Mercy and bleeding keep their existing behavior, and recovery healing adds Trauma once. Effective VIT sets death/concentration rules while maximum Health uses current VIT × level plus explicit Max Health gear. Rendering no longer changes downed flags; loading/saving reconciles tracker defaults without gameplay events. Turn/rest now share the command boundary; broader transaction Undo remains a follow-up.
- **Atomic turns and rests:** Start my turn resets AP/reactions/movement and carries fresh Command once, regenerates visible resources, ticks abilities, reconciles reduced resource maxima, ticks manual statuses, then applies bleeding. Long rest refills existing pools, resets existing timers/uses and Trauma, in one transaction. Rest Undo restores its owned trackers and Health/Mana/concentration fields while preserving later notes, roll history, stock and manual statuses. Status timers do not expire on rest; consumables never refill.
- **Custom resources:** independent named pools with current/max, colors/display, manual spend/restore, turn regeneration, long-rest refill, ability costs and form availability.
- **Status Effects:** shows active timed ability effects and their bonuses, plus manually added Buff, Debuff, Condition and Other entries with optional expiration timers. Manual statuses are descriptive until an actual rule applies.
- **Character Battlemap:** blank, Stone Hall and Barrow grids; fog/line of sight, light, terrain, enemies, targeting, AP movement, Surge, free positioning and undo. Its fog-aware planning uses shared `js/routing.js`.
- **Offline DM Room:** import player snapshots and NPCs, initiative/rounds/turns, AP, Health, damage/healing, manual token placement and confirmed AP-based path movement with animation. Finishing combat allows **Reuse roster / Edit setup**. DM encounter positions are distinct from sheet Battlemap positions and do not sync to other devices.
- **Same-browser Player Preview:** `player.html` can display selected player stats/public encounter positions and submit MoveToken/SpendAP/EndTurn in another tab of the **same browser origin**. Seat selection is not authenticated and it **is not** the planned phone-player multiplayer solution.
- **Character save protection:** stale tabs pause autosave after an external character write or clear; export local edits before reloading. Unreadable stored character data is kept, with a raw download recovery action. This guards cooperating current tabs; old cached code and simultaneous localStorage writes still need stronger schema/concurrency safeguards.
- **Independent local autosaves:** ordinary character edits do not rewrite unchanged DM game data. Battlemap edits preserve newer top-level encounter/player updates from another local view; simultaneous edits to the same game section still need the future transactional backend.
- **Cloud Saves:** `cloud.html` automatically connects to the configured Supabase project; users can sign up/sign in, manually save/list/restore/delete private character copies with per-copy revision conflicts and backups. A revision receipt is scoped to the project/account and survives export/import; refreshing the list never advances it. Older local copies must be exported and restored before overwriting an existing cloud row. Cross-device character restore has been tested; **automatic saving and live encounters are not implemented**.

### Known implementation gaps

- DM character imports exclude active temporary ability bonuses from combat stats, retaining current equipment, form bonuses and manual overrides. A visible warning lists each active ability, its bonuses and remaining turns; encounter timers for imported effects are still not implemented.
- Equipment ability text remains descriptive: Use tracks a charge, with listed costs/effects resolved at the table. The Ability Library provides configurable numeric costs/effects. Legacy round items keep their turn reset until an outside limit is explicitly selected. Ability save DCs are displayed for table resolution; the sheet does not roll or apply saves for another character.
- Existing automated tests include many source-text assertions; real browser-click/390px tests need broader coverage.
- No authenticated cross-device DM game, join codes, server-authorized encounter commands, or live multiplayer synchronization.

## Core rules

The Oct 31 Notion Markdown export and review handoff supply current rules; the DM's answers in this session resolve its questions. These replace the previous advancement rules. Implementation status belongs above; these sections describe the target rules.

- Stats: STR, VIT, DEX, AGL, INT, WIS, CHA, FTH. Keep the existing modifier chart, ASIs and hit-die chart. Effective scores include worn gear, forms and active numerical effects.
- Maximum Health = current VIT × level + explicit Max Health bonuses. Maximum Mana/Holy Power = current INT/FTH × (level + 2) + explicit pool bonuses. Changes to a maximum adjust current by the same difference in either direction. A Health increase that recovers a downed character uses normal recovery Trauma; manual corrections do not. A blank current means full. Manual maximum/current overrides remain supported.
- Existing saves keep their current Health/Mana on first migration, with an old/new maximum notice and manual correction. Obsolete Health advancement rolls, lvGear snapshots and settled gear data are removed when saving. ASIs and stat history remain.
- Hit dice heal on a short rest and no longer determine maximum Health. No new daily hit-die allowance is defined.
- Natural Evasion = 12 + AGL modifier + gear/light-armor/ability bonuses. Save DC = 12 + relevant modifier, including Commanding Presence.
- AP starts at 15, +2 at level 5 and every 5 levels after, including past level 20. Manual overrides remain available. Existing tracker display maximum is 40.
- Reactions: 1, +1 at AGL 21, +1 at AGL 28. Surge grants 2 AP of free movement per turn. Wonder/Defy Fate keep existing rules.
- Movement per AP = max(5, 5 + 5 × AGL modifier), plus explicit bonuses. Heavy armor doubles square costs. Eight-direction movement and existing visibility/occupancy rules remain.
- Keep existing initiative, concentration, death threshold, Mercy, Trauma, healing and ASI rules unless stated below.

## Action Points and attacks

- Action tiers: Free 0, Minor 2, Quick 5, Standard 10, Spell 11, Heavy 15, Extended 15+. AP discounts may use any stat except AGL. Minimum cost is half the base rounded up. Command remains a flat 5 AP; an ally receives 2 + CHA modifier, maximum 5, highest grant only.
- Balanced uses STR or DEX; Heavy uses STR; Finesse uses DEX; Paragon uses either. Ranged/thrown use DEX, except ranged Paragon may use either. Paragon AP discount uses the chosen attack stat.
- Heavy/Paragon double only the damage modifier. Heavy requires STR 21, Finesse DEX 21, Paragon both; below the requirement suggest disadvantage and allow manual adjustment.
- Dual attacks require a Light weapon in each hand. Main damage includes its modifier; off-hand damage in a dual attack adds no modifier and is halved, rounded down. A single off-hand attack retains its modifier.
- A natural 20 always hits and cannot be Dodged. Finesse/Paragon hits on natural 18–19 also critical, without natural-20 Dodge immunity. Critical damage uses maximum dice plus every rolled die; Fast Roll does not replace critical dice.
- Weapon dice scale ×2/×3/×4/×5 at levels 5/10/15/20; flat bonuses/modifiers are added once. Fast Roll rolls the base dice once and multiplies. Block dice scale to 2/3/4/5 at the same levels. Above 20 these two tables remain at their last documented tier pending a separate answer.
- Titan's Might replaces Devastate: once per round, after a melee hit, push 5 ft or try to knock prone for no AP; also permits grappling/shoving larger creatures within reason. Melee means a 5 ft weapon range, plus Reach. Outside combat use the separate STR-modifier allowance.
- Singularity still declares before rolling, spends on a miss and affects one chosen dual hand. Narrative outcomes resolve at the table.

## Defenses

Resistance halves damage first. Two-handed hits ignore half the target's Armor Rating, rounded down; Puncture ignores 2 more. Armor Rating then reduces the damage of every hit you take, followed by Block and the existing Overwhelming Force floor. Dodge/Parry retain their established contested/save behavior.

- Armor Rating = VIT modifier + armor, minimum 0; Adamantine Body uses half current VIT rounded down + armor. All displays share the same derived value, including ability bonuses.
- Block = level-scaled d4 dice + STR modifier, or the shield's die size. Block multipliers are explicit item settings. Two arm guards contribute the highest AR once; both special effects still apply. Leg AR requires a paired item or both leg guards.
- Heavy/Medium/Light armor weight is stored per piece; the heaviest worn piece determines armor type. Light adds its Natural Evasion bonus. Heavy doubles square costs and reduces AGL by 1 per armor AR above 3, capped at −3. The penalty applies to the AGL score; derived modifiers/milestones follow that score. Without STR 21 heavy armor suggests disadvantage on attacks, Dodge and AGL saves, while player choice remains available.
- Reactions cannot use the same defense kind twice against the same attack; the sheet should show reminders while retaining manual corrections.

## Death and dying

There are no death saves. At 0 Health or below you're unconscious and bleeding out, and Health keeps going negative.

- **Death Threshold** = level + VIT. You die when Health reaches the negative of it.
- **Death's Mercy:** the first time you go below 0, the damage that takes you negative can't be more than half your
  Death Threshold. After that, damage hits in full. It's the first time you go negative at all, not the first big hit.
- **Bleeding out:** lose 4 Health every turn at 0 or below. Armor Rating and resistance don't reduce it (an artifact
  ability might).
- **Stabilizing:** someone spends 5 AP and rolls d20 + INT mod against DC 12. On a success you stop bleeding but stay
  unconscious. If no one can heal you, 10 minutes of treatment after combat brings you to 1 Health.
- **Indomitable** (VIT 21): when you're dropped below 0, roll d20 + VIT mod against DC 12. On a success you stop
  bleeding but stay unconscious.
- **Trauma:** each time you're reduced to 0 and recover, your Death Threshold drops by 5 until a long rest. If it
  reaches 0, the next time you go below 0 you die.
- **Exhaustion** is being revamped; ignore the current Notion page for now.

## Gear and weapons

- One shared inventory, separate worn profiles per form. Stat/Health/Mana bonuses use current gear and no longer depend on a long rest. Health/Mana decrease with their maximum on removal or form/portrait changes.
- Losing Health from a maximum change is a direct life adjustment. It can cause unconsciousness and ends concentration at 0 or below; it is not damage, spends no Mercy, and causes no damage concentration check. Subsequent real damage can still use Mercy. Existing death threshold rules remain.
- Weapons support Balanced, Heavy, Finesse, Paragon, Light, Two-handed, Versatile, Strapped, Reach, Thrown, Loading, Mount and normal/disadvantage range bands. Versatile has a separate two-handed dice expression. Reach adds 5 ft. Puncture changes Armor Rating; other signature properties give table reminders unless their complete rule is supplied.
- Strapped hand crossbows stack with arm guards without occupying a hand. A separate strapped attachment is supported alongside ordinary arm slots.
- Loading stores shots remaining and reload costs 5 AP. Quickdraw draw/swap is free. Mount bonuses use distance moved straight before the attack, +1 per 10 ft up to the attack modifier; unmounted use suggests disadvantage.
- Inventory capacity = 10 + STR modifier, plus backpack bonus (normally +6). Worn/held gear is free; two-handed weapons and shields use 2 slots; ammunition and potions stack 5 per slot. Capacity is a warning, never an editing restriction.
- Manual Bleeding is the status effect. Zero-Health loss is named Dying on the sheet to distinguish it. Burning requires the Shake It Off roll, and does not end merely by spending 5 AP.
- Shake It Off: base 5 AP with VIT discount, d20 + VIT modifier against the effect DC; success ends an eligible Bleeding/Burning/Poisoned status. Preset conditions are editable and resolve at the table unless an explicit numeric behavior is defined.

## Source limitations and pending rules

The uploaded Oct 31 Notion Markdown export supplies the exact milestone/condition descriptions and base weapon/armor/shield tables. Direct DM answers override it: AP keeps scaling above 20; Heavy AGL penalty caps at 3; Burning needs a roll; Mana falls with its maximum; maximum-related Health loss spends no Mercy and downed characters stop concentrating; Paragon discounts use the attack stat; the zero-Health state is called Dying; Strapped stacks with guards; obsolete advancement data is deleted; melee means 5 ft plus Reach.

Burning defaults to editable DC 12 because the revised roll rule supplied no DC. Short rest offers one explicit hit-die roll without inventing a daily allowance. Block, weapon dice and source-level status dice stay at the last documented tier above 20; only AP was explicitly extended. Fractional dice-multiplier results round down before adding the modifier. Backpack capacity bonuses currently sum as editable equipment bonuses; quantities and capacity remain correctable. Spell defaults, exhaustion redesign, Currency, Temporary Health, custom-resource overflow and live multiplayer remain separate. Full automatic status enforcement/periodic damage and target signature effects remain table-resolved; the sheet provides descriptions and explicit actions/rolls.

## Direction: customizable characters

Eight stats, AP and the homebrew combat system are the core, while character resources, abilities, statuses, forms and transformations stay customizable. Those editors and automatic ability effects **are already implemented**; the unbuilt refinements are above.
